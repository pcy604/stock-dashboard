## 5. "find skill" = `npx skills` 와 `findskill`

### 정체

차니가 들은 건 둘 중 하나다. 둘 다 실물이 있다.

| | 무엇 | 별 | 마지막 푸시 |
|---|---|---|---|
| **`vercel-labs/skills`** | `npx skills` 명령 자체. "오픈 에이전트 스킬 생태계" — 스킬 검색·설치 CLI | 40,330 | 2026-11-17 |
| **`KimYx0207/findskill`** | **윈도우 호환판** — `npx skills` 가 윈도우에서 빈 출력을 내는 버그를 고친 것 | 125 | **2026-08-12 (3개월 정지)** |

`npx skills` 가 표준 설치기다. Supabase 공식 안내도 `npx skills add supabase/agent-skills` 를
쓴다. `findskill` 은 그게 **윈도우에서 안 되니까** 나온 우회로다 — 차니가 쓰는 환경이 정확히 윈도우 11 이다.

### 추천 ① `npx skills` 먼저 써보고, 빈 출력이 나올 때만 findskill

```bash
npx skills search backtest
```

이게 결과를 내면 `findskill` 은 필요 없다. 빈 출력이면 그때 `findskill` 을 본다.

**깨지는 지점을 먼저 적는다**: `findskill` 은 별 125개에 3개월째 커밋이 없다. `npx skills` 가
1.9.0 까지 올라간 사이(11-16 릴리스) 따라가지 않았을 가능성이 크다. 즉 **지금 깔면 옛 버그를
고친 옛 버전**일 수 있다. 윈도우 문제가 이미 상류에서 고쳐졌을 수도 있으니 순서가 중요하다.

### 추천 ② 스킬 탐색 문제를 CLAUDE.md 로 푼다 (돈·의존성 0)

리서치에서 나온 가장 쓸 만한 사실: 어떤 도구도 아니고 **CLAUDE.md 에 "작업 전에 스킬 목록을
먼저 본다" 는 상시 규칙 한 줄을 넣는 것**이 발견율을 크게 올렸다는 실측 보고가 있다
(897개 스킬 테스트 저장소에서 58작업 중 7 → 40). 수치의 출처는 블로그 한 곳이라 그대로 믿지는
않지만, **비용이 0이고 되돌리기도 쉽다.** 우리 `.claude/skills/README.md` 는 이미 표로
"언제 쓰나" 를 적어 뒀으니 CLAUDE.md 가 그 표를 가리키게만 하면 된다.

## 5-b. "다른 AI 토큰까지 땡겨 쓰는 것"

Claude Code 는 `ANTHROPIC_BASE_URL` · `ANTHROPIC_AUTH_TOKEN` 두 환경변수만 보기 때문에,
그걸 다른 제공자로 돌리면 같은 CLI 로 GLM · DeepSeek · Kimi · Qwen · Gemini · GPT 를 쓸 수 있다.
그걸 자동화한 게 라우터들이다.

| 저장소 | 별 | 마지막 푸시 | 미해결 이슈 |
|---|---|---|---|
| `musistudio/claude-code-router` | 38,291 | 2026-11-21 | **1,153** |
| `decolua/9router` | 32,708 | 2026-11-16 | **2,878** |
| `aryan877/claude-proxy` | 23 | 2026-07-14 | 0 |

### 추천하지 않는다 — 우리 경우엔 손해다

셋 다 안 쓰는 걸 권한다. 이유를 숨기지 않고 적는다.

1. **미해결 이슈가 1,000~2,900개다.** 활발하다는 뜻이기도 하지만, 우리 작업 경로에
   로컬 프록시를 하나 더 끼우는 비용이다. 이 프로젝트의 고질병이 "조용히 안 도는 것" 인데
   프록시는 그 종류의 고장을 하나 더 늘린다.
2. **우리 병목은 토큰이 아니다.** 이 세션에서 실제로 시간을 먹은 건 모델 비용이 아니라
   48MB 패널 내려받기, 테스트 80초, 윈도우 인코딩이었다.
3. **라우터는 Claude Code 를 다른 모델로 바꾸는 것**이지, 토큰을 합치는 게 아니다.
   GLM 으로 돌리면 결과물이 GLM 품질이 된다. 백테스트 숫자·규제 문구를 다루는 작업에서
   싼 모델로 내리는 건 절약이 아니라 사고 확률이다.
4. **이미 멀티모델을 쓰고 있다.** `gemini_client.py` 가 있고 화면 AI 질문은 Gemini·Groq 키를
   쓴다. 싼 모델이 필요한 자리(대량 요약)에는 이미 들어가 있다.

**바꿀 생각이면 순서가 있다.** 라우터를 먼저 깔지 말고, `research/` 의 대량 실험 스크립트
같은 "결과 검증이 쉬운" 작업 한 종류만 골라 Gemini 로 돌려 비용·품질을 측정한 다음 넓힌다.

### 판단: 발행 계층은 우리 것을 쓰고, 콘텐츠 스킬만 참고

우리는 이미 `buza-bot/social/` 에 큐·승인·Threads/X/Instagram API 파이프라인을 **완성해 뒀다**
(`publish_threads.py` · `publish_instagram.py` · `cli.py` · `adapt.py`). 남은 건 Meta·X 앱 토큰
하나다. 저 스킬들이 하는 "발행" 은 전부 **Publora 같은 유료 중개 서비스로 보내는 것**이다.

- 우리 파이프라인을 저걸로 바꾸면 **월 구독료 + 외부 의존 + 계정 위임**이 생긴다.
- 별이 74개와 0개다. **검증된 게 아니다.** 이걸 발행 경로에 넣는 건 과하다.
- 반대로 저 스킬들의 **쓸 만한 부분은 콘텐츠 공식**이다 — "훅을 첫 125자에",
  "목표(저장·공유·댓글·팔로우)별로 훅 공식을 고른다" 같은 것. 그건 MIT 라이선스고
  **코드 의존 없이 글만 가져올 수 있다.**

**추천 ③**: `sergebulaev/threads-skills` 와 `instagram-skills` 의 SKILL.md 에서 훅·캡션 공식만
읽어 **우리 `social/adapt.py` 의 문구 규칙에 녹인다.** 스킬로 설치하지 않는다.
설치하면 Publora 전제가 따라 들어온다.

**깨지는 지점**: 저 공식들은 영어권 Threads·Instagram 기준이다. stock_studian 은 한국어
주식 콘텐츠다. 훅 길이(125자)는 한글에서 다르게 작동하고, 무엇보다 **유사투자자문 규제**
때문에 "이 종목 사라" 류 훅은 우리가 못 쓴다. 그대로 베끼면 규제 사고가 된다.

## 7. 사업 운영 관점 — 진짜로 빈 자리

차니가 가진 스킬을 역할로 깔아 보면 이렇다.

| 사업 기능 | 지금 | 상태 |
|---|---|---|
| 제품 기획·우선순위 | pm · kill-or-keep · loose-ends · prior-art-check | ✅ 충분 |
| 개발 품질 | verification-before-completion · systematic-debugging · writing-plans · webapp-testing | ✅ 충분 |
| 리서치·분석 | earnings-\* · thesis-tracker · comps-analysis · dcf-model · stock-deep-dive | ✅ 과잉에 가깝다 |
| 마케팅·수익화 | growth-chief · pricing · onboarding · launch · ship-public · social-marketing | ✅ 충분 |
| 기록·판단 추적 | decision-log · dev-log · project-cards | ✅ 충분 |
| **고객 지원** | VOC 탭은 **만들었지만**(11-20) 들어온 걸 처리하는 절차가 없다 | 🟡 빈 자리 |
| **규제 대응** | 없음 | 🔴 **가장 큰 빈 자리** |
| **세무** | PIT-38 조사 문서만 있다(11-12). 계산·신고 절차 없음 | 🟡 빈 자리 |

### 🔴 규제가 유일하게 심각한 빈 자리다

외부 사용자 3명이 목표다. **사람이 돈을 내거나 투자 판단에 쓰기 시작하는 순간
유사투자자문업(자본시장법) 신고 문제가 생긴다.** 지금 대응은 "공개 문구에 자동매매·운영자
매매를 쓰지 않는다"(11-15 차니 결정) 같은 **문구 회피**뿐이다. 그건 규제 설계가 아니다.

오픈소스 스킬 중에 이걸 해주는 건 **없다.** 리서치해 봤지만 `legal:compliance-check` 류
플러그인은 전부 미국 기준(GDPR·SOX·주 규제)이고 한국 자본시장법은 다루지 않는다.
즉 **이건 스킬로 메울 수 없고, 사람(금융 쪽 아는 사람)에게 한 번 물어야 하는 항목이다.**

할 수 있는 건 이것뿐이다 — 우리가 **직접 프로젝트 스킬을 하나 쓴다**.
`.claude/skills/` 에 `kr-fin-compliance` 를 만들어, 공개 문구를 발행 전에 검사하는 체크리스트를
담는다(단정적 매수·매도 권유 · 수익률 보장 · 특정 종목 추천 · 회원 모집 표현 · 유료화 표현).
근거 조문과 차니 결정을 같이 박아 두면, 세션이 바뀌어도 같은 기준으로 걸러진다.
이건 `skill-creator` 로 만들 수 있고 외부 의존이 0이다.

### 🟡 VOC 처리 절차

VOC 탭을 만들었는데 **들어온 글을 누가 언제 어떻게 처리하는지가 없다.** 외부 사용자 3명이
목표라면 첫 민원 하나가 그 사람 전부다. 세션에 이미 `customer-support` 플러그인 스킬
(ticket-triage · draft-response · customer-research)이 깔려 있다 — **새로 설치할 게 아니라
그냥 쓰면 된다.** 다만 인증이 필요한 서버(Intercom·HubSpot 등)에 묶여 있지 않은지 확인이 필요하다.

### 🟡 세무

`docs/research/2026-11-12_세금·고정IP.md` 에 조사가 돼 있고, 그 안에 이미
"연말에 PIT-38 계산표를 뽑는 스크립트 하나면 된다(백로그)" 라고 적혀 있다.
**스킬이 아니라 스크립트 한 개 문제다.** `live/trades.jsonl` 에 체결일·가격·수수료가
다 있으니 원화→PLN(NBP D-1) 환산표를 만들면 끝난다. 귀국(12-14)과 연말이 겹치니
**12월 안에 하는 게 맞다.**

## 정리 — 할 것 3개, 안 할 것 명시

### 할 것

1. **`npx skills search` 한 번 돌려 보기.** 윈도우에서 빈 출력이면 그때만 `findskill`.
   그리고 CLAUDE.md 에 "작업 전 스킬 목록 확인" 한 줄. (비용 0)
2. **`kr-fin-compliance` 프로젝트 스킬 직접 만들기.** 오픈소스에 없다. 외부 사용자가
   생기기 전에 있어야 한다. (가장 중요)
3. **PIT-38 계산표 스크립트.** 12월 안에. 이미 백로그에 적혀 있던 것.

### 안 할 것 (이유 있음)

- **멀티모델 라우터** — 우리 병목이 토큰이 아니고, 조용히 깨지는 경로를 하나 늘린다.
- **SNS 발행 스킬 설치** — 우리 파이프라인이 이미 있고, 저쪽은 유료 중개 전제다. 글만 참고.
- **새 스킬 목록 저장소 뒤지기** — 가장 큰 두 곳(anthropics·superpowers)에서 이미 뽑아 왔다.
- **customer-support 스킬 설치** — 이미 세션에 있다. 설치가 아니라 사용 문제.
