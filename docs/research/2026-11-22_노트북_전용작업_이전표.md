# 노트북에서만 돌아가는 작업 — 전수 목록과 이전표

2026-11-22 · 백로그 #2 · 목표: **12-14 귀국 전에 노트북 의존을 끊는다**

노트북이 꺼지면 멈추는 것이 무엇인지 코드가 아니라 **실제로 등록된 작업 스케줄러**부터
확인했다. Desktop 아래 전 프로젝트의 `.bat`·`.ps1`·`.vbs`·`.sh` 도 함께 훑었다.

## 1. 지금 실제로 등록돼 돌고 있는 작업 (3개)

`Get-ScheduledTask` 로 확인한 사용자 작업 전부다. 나머지 Windows·OneDrive·LG 항목은 우리 것이 아니다.

| 작업 이름 | 부르는 것 | 주기(현지 시각) | 마지막 결과 | 실제로 하는 일 |
|---|---|---|---|---|
| `StockScreener_Daily` | `run_update.bat` | 매일 06:00 | 0 (정상) | `tools/toss_sync.py` — 토스 잔고 동기화 → `data/portfolio_toss.vault` 커밋·푸시 |
| `buza_live_bot` | `run_live_bot.bat` | 평일 00:40·01:10·08:40·09:10 | 0 (정상) | `live/bot.py --send` — 실전 시범 주문·체결 확인, 원장 커밋·푸시 |
| `StockScreener_LeadersWeekly` | `run_leaders_weekly.bat` | 매일 08:00 | **2 (실패)** | `leaders_weekly.sh` — 주도주 주간 사이클. **Actions 가 이미 같은 일을 한다** |

### 이전 가능 여부

| 작업 | Actions | Supabase | 판정 | 방법 |
|---|---|---|---|---|
| `StockScreener_Daily` (토스 잔고) | ❌ | ❌ | **고정 IP 서버로만** | 토스 Open API 는 WTS 에 등록한 **허용 IP 에서만** 응답(미등록 403). Actions 러너 IP 는 매번 바뀐다. Supabase 는 저장소라 호출 주체가 될 수 없다(Edge Function 도 IP 고정 불가). → Oracle Always Free VM + 예약 공인 IP. 절차는 [2026-11-12_세금·고정IP.md](2026-11-12_세금·고정IP.md) 2절 |
| `buza_live_bot` (주문 봇) | ❌ | ❌ | **고정 IP 서버로만** | 위와 같은 이유. 주문까지 하므로 더 엄격하다 |
| `StockScreener_LeadersWeekly` | ✅ **이미 됨** | — | **즉시 폐기** | `weekly-accel.yml` 이 `leaders_build fetch/update` → `leaders_accel.py` → `leaders_accel.json`·`price_curves.json` 을 금 22:17 / 토 06:17 / 토 14:17 / 일 02:17 UTC 에 만든다. 노트북 산출물과 같은 파일이다 |

**결론: 노트북이 꼭 필요한 일은 토스 관련 2개뿐이다.** 둘의 공통 블로커는 하나 — 허용 IP.
고정 IP 서버 하나를 세우면 노트북 의존이 완전히 끊긴다. 그 밖에는 옮길 것이 없다.

## 2. `StockScreener_LeadersWeekly` 는 초록불이 아니었다

마지막 결과 코드 2. 로그를 열어보니 **두 군데가 깨져 있다.**

1. `leaders_build.py:786` — 산출물 경로 기본값이 리눅스 전용이다.
   ```
   FileNotFoundError: [Errno 2] No such file or directory: '/tmp/accel_week.json'
   ```
   `os.environ.get("ACCEL_WEEK_STATS", "/tmp/accel_week.json")` — Actions(우분투)에서는 되고
   Windows 에서는 `/tmp` 가 없어 매번 터진다. `results/leaders_weekly_20261121.log` 의 끝.

2. `run_leaders_weekly.bat` 파일 자체가 손상됐다. 이전 편집에서 경로 안의 `\r` 이
   **실제 캐리지리턴으로 바뀌어 한 줄이 두 줄로 쪼개졌다**. 두 곳:
   - 주석 줄 `.git\rebase-merge` → `ebase-merge ...` 가 독립 줄이 되어 cmd 가 명령으로 실행을 시도
   - 마지막 원격 확인 줄 `%DIR%\results\leaders_accel.json` → `esults\leaders_accel.json'...` 고아 줄

즉 **같은 산출물을 Actions 가 매주 정상으로 만드는 동안, 노트북은 매일 아침 8시에 실패하고 있었다.**
초록불로 보인 이유는 실패해도 아무도 보지 않는 종료 코드였기 때문이다.

### 조치

- 작업 스케줄러에서 `StockScreener_LeadersWeekly` **비활성화**(2026-11-22 실행). 되살리려면:
  ```bash
  powershell -Command "Enable-ScheduledTask -TaskName StockScreener_LeadersWeekly"
  ```
- 파일 폐기(`run_leaders_weekly.bat` · `leaders_weekly.sh`)는 **하지 않았다.** 지우는 건 차니 판단.
  고치지 않은 이유: 고쳐서 되살리면 Actions 와 **같은 파일을 두 주체가 커밋**해 리베이스 충돌이 난다.
  수동 더블클릭 경로가 필요 없으면 두 파일을 지우는 게 맞다.
- `/tmp/accel_week.json` 기본값은 Actions 에서는 문제가 없어 **이번에 건드리지 않았다.**
  로컬에서 `leaders_build.py` 를 직접 돌릴 일이 생기면 그때 `tempfile.gettempdir()` 로 바꿀 것.

## 4. 12-14 귀국 전 할 일 (차니 몫)

1. **Oracle Always Free VM + 예약 공인 IP 1개** 만들기(약 30분). 절차는
   [2026-11-12_세금·고정IP.md](2026-11-12_세금·고정IP.md) 2절 1~3번.
2. 토스 WTS → 설정 → Open API → 허용 IP 에 그 IP 추가. **노트북 IP 는 당분간 같이 둔다**(대조용).
3. 그 IP 를 알려주면 Claude 가 `crontab` 설치 스크립트를 만든다 —
   `toss_sync`(매일 06:00 KST) · `live/bot.py`(평일 08:40·09:10 KST).
4. 1주일 동안 노트북·서버를 **둘 다 모의로** 돌려 같은 판단인지 대조한 뒤 서버만 실전으로.
5. 대조가 끝나면 노트북 작업 2개 비활성화 + 토스 허용 IP 에서 노트북 IP 제거.

이 순서를 지키면 귀국 비행기에서 노트북을 닫아도 멈추는 게 없다.
