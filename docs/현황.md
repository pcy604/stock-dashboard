**이 파일이 `claude/01_현황.md` 의 정본이다 (2026-11-22 이관).**
claude.ai 프로젝트 문서 `claude/01_현황.md` 는 이 파일을 가리키는 포인터로만 남긴다 — 거기에 내용을 쓰지 말 것.

이관 이유 — `02_changelog` 를 11-15 에 옮긴 것과 같다. 거기에 둘을 더한다:
1. **Claude Code 는 claude.ai 프로젝트 지식 문서를 읽을 수 없다.** 아티팩트·Docs 와 다른 저장소이고

   그래서 "01_현황 의 다음 할 일을 진행" 같은 지시가 코드 세션에서 **수행 불가**였다.
2. 프로젝트 문서는 덧붙이기가 안 돼 한 줄 고치려면 전문을 다시 쓴다.

운용 규칙
- 작업을 마치면 `docs/changelog.md` 에 한 줄(사건·의미), **이 파일에는 상태**(지금 무엇이 열려 있나)를 갱신한다.
- 설계·결정의 긴 근거는 `docs/research/<날짜>_<주제>.md` 에 두고 여기서 링크한다.
- 이 파일은 짧게 유지한다. 끝난 것은 changelog 로 내려가고 여기서 지운다.

| 열 | 전 | 후 | 원인 |
|---|---|---|---|
| 미국 업종 | 0% | 99.59% | `leaders_build` 가 `factor_weekly.sector` 에 `None` 을 하드코딩 |
| 미국 이익 개선폭 | 열 없음 | 64.02% | 한국에만 있던 지표 — 같은 식·같은 %p 로 미국에도 |
| 한국 이익 개선폭 | 0% | 52.67% | `kr()` 가 줄곧 계산했는데 `COLS` 에 없어 버려졌다 |
| 한국 매출 QoQ | 0% | 70.76% | 열만 있고 계산이 없었다 |

재발 방지: `quant_panel.MUST` — 그 시장에서 값이 있어야 하는 열이 0%면 빌드를 세운다(빈 패널을 릴리스에 올리지 않는다).
불변식 테스트: 엔진 `_BASE` ⊆ 패널 `COLS`.

### 분기 데이터 난립 (11-22 실측 — ‘주도주 분기 데이터 정리’의 실체)
한국 분기 재무가 **두 벌**로 갈라져 있고 서로 맞지 않는다:

| 저장소 | 행 | 종목 | 기간 |
|---|---|---|---|
| `market.db` `fundamentals_q` | 43,792 | 1,466 | 2017~2026 |
| `data/kr_fundamentals_q.parquet` | 89,340 | 2,536 | 2016~2026 |

- 한쪽에만 있는 행 **46,694개** (DB 전용 573 · parquet 전용 46,121)
- 둘 다 값이 있는 칸 중 1% 넘게 다른 것: 매출 242 · 영업이익 348 · 순이익 133
- 최대 상대차 **10^6 배** — 단위(원 ↔ 억원) 오류가 섞여 있다

여기에 미국 쪽 분기 재무까지 더하면 분기 데이터 저장소가 7곳이다:
`fq_{sym}.csv` 캐시 2,853개 · `factor_weekly` · `fundamentals_q` · `kr_fundamentals_q.parquet` ·
`fundamentals`(한국 연간 2023~2025만) · `consensus_q.json` · `_fw_v13y.parquet`.

→ 정본 하나를 정하고, 어긋난 칸을 원인별로 분해하고, 재생성 경로와 감시를 붙이는 것이 ‘정리’의 내용이다.
